# Graceway 교회 사진 갤러리 구현 계획

## 목적과 디자인 방향

이 갤러리는 예배, 기도회, 교제, 캠퍼스 사역, 특별 행사의 실제 모습을 차분하고 존중하는 방식으로 기록하는 공간입니다. 기존 Graceway 사이트의 **Grace Navy·슬레이트·아이보리·절제된 골드** 팔레트와 편집형 타이포그래피를 유지하되, 사진 자체가 중심이 되도록 과도한 장식은 줄입니다. 방문자는 한 장의 대표 사진으로 앨범의 분위기를 먼저 느끼고, 필요할 때만 사진을 크게 열어 볼 수 있어야 합니다.

## 벤치마킹에서 반영할 점

| 관찰한 패턴 | Graceway 적용 방식 |
| --- | --- |
| 교회 사이트는 사진 갤러리와 콜라주를 독립된 콘텐츠 경험으로 제공한다.[1] | 공개 메뉴에 **갤러리**를 추가하고, Home에는 최신 앨범 1개와 사진 3장을 보여 주는 작은 연결 섹션만 둡니다. |
| 썸네일 격자에서 사진을 선택해 큰 이미지로 보는 흐름은 많은 사진을 부담 없이 탐색하게 한다.[2] | 균일한 비율의 앨범 카드와 사진 타일을 사용하고, 선택 시 키보드 탐색 가능한 전체 화면 뷰어를 엽니다. |
| 진정성 있는 공동체 사진은 교회 웹사이트의 신뢰와 환대에 도움이 된다.[3] | 스톡 이미지가 아니라 관리자 승인된 실제 예배·행사 사진만 공개하며, 촬영일·행사명·간단한 캡션을 선택적으로 표시합니다. |

## 권장 공개 경험

공개 경로는 **`/gallery`**로 신설합니다. 상단에는 최신 또는 대표 앨범 한 개를 넓은 사진과 함께 소개하고, 그 아래에는 연도·유형(예배, 기도, 교제, 사역, 특별 행사) 필터와 앨범 카드 목록을 둡니다. 앨범 카드는 대표 사진, 제목, 날짜, 사진 수를 보여 주며, 앨범 안에서는 3:2 비율의 정돈된 사진 그리드를 사용합니다. 사진을 선택하면 전체 화면 뷰어에서 이전·다음, 닫기, 사진 설명을 제공하고, `Esc`와 화살표 키도 지원합니다.

모바일에서는 대표 앨범, 필터, 두 열 사진 타일, 화면 전체 뷰어 순으로 자연스럽게 바뀝니다. 카드와 뷰어의 움직임은 기존 사이트와 맞춰 200–300ms 이내의 짧은 투명도·변형 전환만 사용하며, 움직임 축소 환경설정도 존중합니다.

## 관리자와 사진 보호 원칙

`/admin`에 **Gallery** 관리 탭을 추가합니다. 관리자는 앨범을 만들고, 여러 사진을 끌어 놓거나 파일 선택으로 올린 뒤, 한국어·영어 제목, 행사 날짜, 유형, 대표 사진, 사진 순서, 공개 상태를 관리합니다. 사진 원본은 사이트 저장소에, 앨범과 사진 메타데이터·공개 상태는 데이터베이스에 저장합니다.

공개 전에는 교회가 필요한 촬영·초상권 동의를 직접 확인해야 합니다. 특히 미성년자, 민감한 돌봄 현장, 개인 기도 요청이 보이는 사진은 기본적으로 공개하지 않고, 관리자가 명시적으로 게시할 때만 노출합니다. 공개 페이지는 비공개·보관·삭제된 사진을 절대 반환하지 않으며, 사진 설명은 접근성 대체 텍스트로도 사용합니다.

## Google Photos 연동의 실제 범위

Google Photos는 기존 개인 앨범 전체를 서버가 지속적으로 읽어 자동 동기화하는 방식에 더 이상 적합하지 않습니다. 2025년 3월 이후 Library API는 애플리케이션이 생성한 앨범과 미디어만 장기적으로 조회할 수 있으며, 공유 앨범 관련 기능도 제한됩니다.[4] Google Photos API는 서비스 계정을 지원하지 않고 OAuth 2.0 동의가 필요합니다.[5]

따라서 Google Photos에서는 **관리자가 가져오기 때마다 직접 선택하는 방식**을 권장합니다. 관리자가 Gallery 탭에서 ‘Google Photos에서 가져오기’를 누르면 Google의 사진 선택 화면이 열리고, 앨범 또는 사진을 명시적으로 선택합니다. 선택된 사진만 사이트 저장소에 복사하고, 해당 앨범의 공개 전 검토 목록에 추가합니다. 이 방식은 개인 사진 전체에 대한 상시 접근 권한을 요구하지 않고, 관리자가 매번 공개 범위를 통제할 수 있습니다.[6]

## 구현 선택지

| 선택지 | 운영 방식 | 장단점 | 초기 설정 |
| --- | --- | --- | --- |
| **A. 수동 업로드 + Google Photos 명시적 선택 — 권장** | 관리자가 파일을 직접 올리거나, Google Photos에서 앨범·사진을 선택해 가져온 뒤 공개합니다. | 사진 공개 범위를 매번 검토할 수 있고 기존 Google Photos 사진을 활용합니다. Google OAuth 설정이 필요하며, 기존 앨범의 자동 동기화는 제공하지 않습니다. | 중간 |
| **B. 수동 업로드 + Google Drive 폴더 동기화** | 행사별 Drive 폴더의 사진을 가져와 앨범 후보로 저장합니다. | 주보 자동 동기화처럼 폴더 단위 반복 작업에 적합합니다. Google Photos가 아니라 Drive로 사진을 복사해야 합니다. | 낮음–중간 |
| **C. 수동 업로드만으로 1차 공개** | 관리자가 Gallery 탭에서 사진을 올리고 공개합니다. | 가장 빠르고 안전하게 시작할 수 있습니다. Google Photos의 기존 앨범을 직접 가져오지는 않습니다. | 낮음 |

## 단계별 일정

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| 1. 정보 구조 확정 | 공개 `/gallery` 경로, 앨범 유형, 대표 사진, 사진 보호 기준을 확정합니다. | 관리자와 공개 페이지가 같은 앨범·사진 용어를 사용합니다. |
| 2. 저장 모델과 관리자 업로드 | 앨범·사진 테이블, 관리자 CRUD, 다중 파일 업로드, 공개 상태·정렬을 만듭니다. | 관리자가 사진을 올리고 검토 후 공개할 수 있습니다. |
| 3. 공개 갤러리 | 필터, 앨범 상세, 전체 화면 뷰어, Home 연결을 만듭니다. | 방문자가 모바일·데스크톱에서 사진을 안정적으로 탐색합니다. |
| 4. Google Photos 선택 가져오기 | OAuth 동의, 사진 선택, 저장소 복사, 중복 방지·실패 안내를 만듭니다. | 관리자가 선택한 사진만 앨범 초안으로 가져옵니다. |
| 5. 검증과 운영 문서 | 권한·비공개 필터·업로드 제한·키보드 뷰어·반응형 테스트를 수행합니다. | 공개되지 않은 사진이 노출되지 않고, 관리자 운영 절차가 문서화됩니다. |

## 다음 결정

우선 **A/B/C 중 하나를 선택**해야 합니다. A를 선택하면 다음 단계에서 Google Cloud OAuth 앱의 클라이언트 ID와 비밀값을 안전하게 연결하고, Google Photos Picker의 명시적 선택 흐름을 구현합니다. B나 C를 선택하면 외부 OAuth 설정 없이 수동 업로드 중심의 공개 갤러리를 먼저 출시할 수 있습니다.
